# Catalogue integration

The primary source is the official [MusicBrainz API](https://musicbrainz.org/doc/MusicBrainz_API), verified 3 November 2026. Search uses `/ws/2/recording?query=…&fmt=json`, documented [recording/artist/tag search fields](https://musicbrainz.org/doc/MusicBrainz_API/Search). Each response is normalized using actual recording IDs, artist credits/join phrases, available release titles, durations, tags and ISRCs. Missing fields remain empty. Different recordings are kept separate in search; the ranking layer later suppresses obvious versions.

Direct cross-origin fetch worked in the actual browser from the local static app. No traditional backend or serverless proxy is included. Browser-controlled User-Agent is never overwritten; the public application identity is supplied as a `client` query parameter and origin referrer where permitted. This supplements identification; it does not change the browser's User-Agent. Do not assume browser identification is equivalent to a custom server User-Agent. Usage is an educational/non-commercial demo; MusicBrainz requires arrangements for commercial service use.

The [rate policy](https://musicbrainz.org/doc/MusicBrainz_API/Rate_Limiting) limits clients to one request/second. An origin-wide Web Lock serializes requests across tabs and holds each slot for at least 1.1 seconds. Each retry uses that gate. A shared 24-hour/30-query cache avoids repeat requests, and input debounce plus cancellation prevents stale results. Per-IP/global throttling can still happen across different origins/users on the same network. Browsers without secure-context Web Locks use the labeled fallback. 429/503 honor bounded Retry-After; long cooldowns immediately fall back. Requests time out after 7 seconds with one timeout retry. No custom forbidden headers are set.

Fallback records are a small verified demo subset, not a global catalogue and not live data. See [provenance](../frontend/data/README.md). No secondary API is used: illustrations avoid added requests and artwork-licensing ambiguity. They are explicitly not album covers.

If direct CORS later changes, retain fallback instead of adding an uncoordinated serverless proxy. Any future proxy must have a shared/global upstream limiter (an in-memory function-instance limiter is insufficient), honest origin handling and reviewed free-tier limits. Current deployment has zero functions.
